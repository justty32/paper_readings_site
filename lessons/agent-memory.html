研究怎麼做？把例子接回論文

長期記憶不只是把更多文字塞回提示。AtomMem 從對話選取自包含的原子事實，處理指代與相對時間，再組成事件與時間檔案，檢索時沿關聯找回碎片資訊。這讓「他上週搬家」可以變成指向明確人物與日期的記錄，而不是下次讀到仍得猜他是誰。〔2606.19847〕

記錄清楚之後，還要決定留什麼。CURATOR 研究端側 agent 的經驗記憶，以價值減危害、再除以位元組的分數處理保留、分享與信任。它把過時資訊和可疑來源一起納入治理。這是在特定凍結 planner 與資源約束下的設計，不能解讀成所有記憶越少越好。〔2606.25115〕

本課練習：試著把一句含有「他」「明天」「還是老樣子」的對話，改成離開原對話也看得懂的記錄。資訊不足時先標出缺口，別自己補成確定事實。這是教學練習；精簡的目標是方便可靠地重用，而不是讓每筆記憶看起來都很完整。

記憶放在哪裡

兩篇這裡處理的是外部可檢索記憶，並不代表模型權重因每次聊天就更新。〔2606.19847〕〔2606.25115〕

不同問題分層解

AtomMem 的重點是表示與召回；CURATOR 的重點是預算下的經驗治理，應看清兩者評測情境不同。〔2606.19847〕〔2606.25115〕

兩個容易混淆的地方
  • 抽取事實若錯，後續精巧檢索也會沿用錯誤。〔2606.19847〕
  • 來源標籤不是來源證明，CURATOR 仍討論偽造來源的攻擊。〔2606.25115〕

這些想法，從哪幾篇開始？

下方連到原始論文，以及固定快照中的已讀筆記。課程是入門導讀；教學類比與互動不代表論文曾做過的實驗。

  1. AtomMem

    原子事實、事件與時間檔案。

    問題
    長對話的資訊分散且偏好會變，如何避免粗摘要、噪聲與無約束改寫破壞記憶。 〔2606.19847〕
    方法
    抽取自包含原子事實，組成事件與時間檔案，檢索時沿聯想圖召回相關事實。 〔2606.19847〕
    邊界
    主要評測為長對話記憶，依賴微調抽取器品質，不能直接推論到所有具身長任務。 〔2606.19847〕

  2. CURATOR

    每位元組淨值與記憶治理。

    問題
    端側經驗記憶受容量、能量與上行限制，也可能留下過時或被投毒的高風險條目。 〔2606.25115〕
    方法
    以價值減危害再除位元組的淨值密度，在預算下決定保留、分享與信任條目。 〔2606.25115〕
    邊界
    以凍結規劃器為前提，治理經驗而非運動策略；來源先驗不等於不可偽造的證明。 〔2606.25115〕
