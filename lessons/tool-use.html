研究怎麼做？把例子接回論文

ReAct 讓推理、行動與觀察交錯。模型可以先提出查詢方向，呼叫外部工具，讀到觀察後再調整。它的文字思考本身不改變環境，實際行動才取得外部回饋。這條分界讓讀者能追查某個判斷來自模型猜測，還是工具觀察。〔2210.03629〕

Toolformer 則研究如何學會何時用工具。它在文字裡生成 API 呼叫候選、執行取得結果，保留能降低後續文字預測損失的呼叫，再拿來微調。它學的是呼叫時機、工具與參數，不是看到所有問題就必須開工具；原文的獨立呼叫設定也還沒有教會一般性的多工具串接。〔2302.04761〕

本課練習：把「打算搜尋」「送出查詢」「收到搜尋結果」分成三張卡片，依序排好。若第二張卡執行失敗，第三張就不能假裝已有觀察。這是教學示意。追蹤每一步的輸入與回傳，可以幫助你讀懂工具軌跡，而不是只看最後一句答覆。

學習和執行不同

Toolformer 在訓練資料建構時篩選呼叫；ReAct 展示推論時交錯安排推理與行動。〔2302.04761〕〔2210.03629〕

能力的範圍

Toolformer 原文不會一般性鏈接不同工具，ReAct 也可能反覆重做相同動作；使用工具仍需要檢查流程。〔2302.04761〕〔2210.03629〕

兩個容易混淆的地方
  • 工具有回覆不代表找到有用證據；ReAct 有被無資訊搜尋拖住的失敗。〔2210.03629〕
  • Toolformer 的保留訊號是後續 token 損失下降，不是每種任務的完整正確性證明。〔2302.04761〕

  1. Toolformer

    自監督篩選有用 API 呼叫。

    問題
    如何讓模型少靠人工標註，就學會何時呼叫哪個工具、給什麼參數並使用回傳。 〔2302.04761〕
    方法
    生成並執行 API 呼叫候選，只保留能降低後續文字預測損失的呼叫來微調。 〔2302.04761〕
    邊界
    原始設定未教會一般性多工具串接或互動搜尋，也未把工具呼叫成本納入篩選。 〔2302.04761〕

  2. ReAct

    推理、行動與觀察交錯。

    問題
    只做內部推理容易缺乏外部證據，只做行動又欠缺高階計畫，如何讓兩者協作。 〔2210.03629〕
    方法
    交錯生成推理、工具行動與環境觀察，讓新證據更新計畫並支撐下一個動作。 〔2210.03629〕
    邊界
    效益依賴觀察品質，無資訊搜尋和重複迴圈仍會失敗，並非工具接上就不會幻覺。 〔2210.03629〕
