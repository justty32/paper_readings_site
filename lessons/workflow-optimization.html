研究怎麼做？把例子接回論文

DSPy 把語言模型流程拆成模組，用簽章寫出輸入與輸出，再讓優化器依任務指標挑選有用示範。你先說「資料和問題進來，答案出去」，不必把整套邏輯塞在一條愈來愈長的提示裡。這裡的編譯主要是優化模型的用法，並不代表執行時不再呼叫模型。〔2310.03714〕

GPTSwarm 把操作當節點、資訊流當邊；不同 agent 也能組成大圖。它分別優化節點提示與跨 agent 連線，讓「誰把什麼交給誰」也成為可測試的選擇。節點變多不等於合作更好，圖本身需要有任務效用來評估。〔2402.16823〕

本課練習：把日常查資料畫成三到五個方框，寫上每個方框收到什麼、交出什麼。再挑一條交接線，想像前一站漏給來源時會發生什麼。這是教學練習；它幫助你把模糊的「AI 不夠好」拆成可觀察的交接問題，尚未證明流程已被改善。

節點與邊

節點改的是單站操作，邊改的是資訊傳遞；兩者對應不同失敗原因。〔2402.16823〕

優化也要付費

搜尋候選圖需要多次執行與評估；應把建置成本與之後使用成本分開看。〔2402.16823〕

兩個容易混淆的地方
  • 評分若只獎勵表面格式，優化未必改善真正任務；本課設計提醒。
  • GPTSwarm 原文對跨 agent 的邊優化，不能一概解讀成任意內部拓撲都已自動搜尋。〔2402.16823〕

  1. DSPy

    簽章、模組與優化器。

    問題
    多階段語言模型流程依賴手寫提示，換模型或資料域時容易脆弱且難以協調。 〔2310.03714〕
    方法
    用簽章描述輸入輸出，模組組合流程，再由優化器依指標挑選有用示範與參數。 〔2310.03714〕
    邊界
    需要可用的任務指標引導編譯；這主要優化模型呼叫，不代表執行時無須模型。 〔2310.03714〕

  2. GPTSwarm

    操作圖、節點與邊優化。

    問題
    多智能體提示與合作方式多靠人工設計，如何把操作和資訊傳遞統一成可優化物。 〔2402.16823〕
    方法
    將操作表示成節點、資訊流表示成邊，分別優化節點提示與跨智能體連線機率。 〔2402.16823〕
    邊界
    原文主要優化智能體之間的邊；需反覆取樣與評分，不能視為任意拓撲免費優化。 〔2402.16823〕
